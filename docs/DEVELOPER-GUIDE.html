First-Time Local Setup

1. Clone and install

git clone <repo-url>
cd tse-ui
pnpm install
A .npmrc at repo root hoists @medusajs/*, react, and react-dom so Vite (Medusa admin bundler) can find them. Do not delete it.

2. Start Docker services

docker-compose up -d

Starts Postgres on :5432 and Redis on :6379. Medusa runs locally, not in Docker.

3. Create backend env file

cp apps/backend/.env.example apps/backend/.env

Minimum apps/backend/.env:

DATABASE_URL=postgresql://postgres:tse_local_dev@localhost:5432/tse_medusa
REDIS_URL=redis://localhost:6379
JWT_SECRET=local-dev-jwt-secret-tse
COOKIE_SECRET=local-dev-cookie-secret-tse
MEDUSA_BACKEND_URL=http://localhost:9000
MEDUSA_WORKER_MODE=shared
DISABLE_MEDUSA_ADMIN=false
STORE_CORS=http://localhost:3000,http://localhost:3001
ADMIN_CORS=http://localhost:9000
AUTH_CORS=http://localhost:9000,http://localhost:3000,http://localhost:3001
MEDUSA_ADMIN_EMAIL=admin@tse.co.za
MEDUSA_ADMIN_PASSWORD=TseAdmin2026!
STOREFRONT_URL=http://localhost:3001

4. Run Medusa migrations

pnpm --filter @tse/backend migrate

5. Start Medusa

pnpm --filter @tse/backend dev

Admin dashboard: http://localhost:9000/app · API: http://localhost:9000

6. Seed the database

pnpm tsx scripts/seed.ts

Idempotent — safe to re-run. Seeds:

  • South Africa region (ZAR)
  • TSE Online Storefront sales channel
  • Category hierarchy: Inkjet Cartridges → brands, Laser Cartridges → brands
  • All 559 products from migration/raw/products.json
  • Links all products to the sales channel

7. Create a publishable API key

# Authenticate
TOKEN=$(curl -s -X POST http://localhost:9000/auth/user/emailpass \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@tse.co.za","password":"TseAdmin2026!"}' \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['token'])")

# Create key
KEY_ID=$(curl -s -X POST http://localhost:9000/admin/api-keys \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"title":"TSE Online Storefront","type":"publishable"}' \
  | python3 -c "import sys,json; d=json.load(sys.stdin); print(d['api_key']['id'])")

TOKEN_VALUE=$(curl -s http://localhost:9000/admin/api-keys/$KEY_ID \
  -H "Authorization: Bearer $TOKEN" \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['api_key']['token'])")

# Link to sales channel (get channel ID from seed output or admin UI)
curl -s -X POST "http://localhost:9000/admin/api-keys/$KEY_ID/sales-channels" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d "{\"add\":[\"$CHANNEL_ID\"]}"

echo "NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY=$TOKEN_VALUE"

Or via admin UI: Settings → API Keys → Create → link to TSE Online Storefront channel.

8. Create web env file

apps/web/.env.local:

NEXT_PUBLIC_MEDUSA_BACKEND_URL=http://localhost:9000
NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY=pk_<your-key>

9. Start the storefront

pnpm --filter @tse/web dev

Storefront: http://localhost:3001

Known Gotchas

SymptomCause & Fix
esbuild version conflict on install pnpm overrides in root package.json pin esbuild to 0.25.6. If missing, re-add the override.
Medusa admin blank screen Requires @medusajs/dashboard, react, react-dom as explicit deps in apps/backend/package.json + .npmrc hoisting. Both committed.
Cannot find module '@medusajs/admin-sdk' @medusajs/draft-order requires @medusajs/admin-sdk@2.13.6 exactly. Pinned via pnpm override.
Cannot find module '@medusajs/framework/utils' apps/backend/tsconfig.json must use moduleResolution: "bundler" (not "node").
ts-node missing Must be in apps/backend/package.json devDependencies. tsconfig includes ts-node: { transpileOnly: true }.
CORS errors in storefront STORE_CORS must include storefront origin. pnpm dev may allocate :3001 if :3000 is taken — set both.
Store API returns 0 products (1) Products must be linked to the sales channel tied to the publishable key. (2) Pass region_id to get calculated_price on variants.
Shipping option creation fails: "Providers not allowed" The fulfillment provider must be associated with the stock location via POST /admin/stock-locations/:id/fulfillment-providers before creating options. The seed script handles this.
GET /admin/fulfillment-sets/:id returns HTML This endpoint does not exist in Medusa v2. Use GET /admin/stock-locations/:id?fields=*fulfillment_sets,*fulfillment_sets.service_zones.

POPIA / Sensitive Data Rules

  • migration/raw/customers.json — NEVER commit — contains real customer PII
  • migration/raw/orders.json — NEVER commit — contains real order history
  • Real customer/order data must only be migrated to the production Vultr JHB server
  • Synthetic data only in seed scripts
