2. First-Run Deploy Sequence

Dependency chain: postgres → redis → medusa-migrate → medusa → web → nginx. nginx has a TLS cert chicken-and-egg — follow this order exactly.

# All commands run from /opt/tse-ui on the VPS
cd /opt/tse-ui
git pull origin main

# 1. Bring up data services + run migrations
docker compose up -d postgres redis
docker compose up medusa-migrate   # foreground — watch all 25 modules complete

# 2. Bring up Medusa (first boot: 30-90s — wait for 'healthy')
docker compose up -d medusa

# 3. Bring up storefront (depends on medusa healthy)
docker compose up -d web

# 4. Issue TLS cert via certbot --standalone (nginx NOT running yet, :80 is free)
#    Single SAN cert covering BOTH domains, stored under live/dev.tse-cartridges.co.za/
docker run --rm -p 80:80 \
  -v tse-ui_certbot_certs:/etc/letsencrypt \
  -v tse-ui_certbot_www:/var/www/certbot \
  certbot/certbot certonly --standalone \
    --non-interactive --agree-tos --no-eff-email \
    --email ryno@trinextinnovations.co.za \
    -d dev.tse-cartridges.co.za \
    -d api.dev.tse-cartridges.co.za

# Verify SAN cert covers both domains
sudo openssl x509 \
  -in /var/lib/docker/volumes/tse-ui_certbot_certs/_data/live/dev.tse-cartridges.co.za/cert.pem \
  -noout -text | grep -A1 "Subject Alternative Name"

# 5. Bring up nginx (cert now exists)
docker compose up -d nginx

# 6. Verify
docker compose ps

Expected: https://dev.tse-cartridges.co.za → Next.js storefront · https://api.dev.tse-cartridges.co.za/health → OK

3. Gotchas (Hit on 2026-05-20)

3.1 medusa db:migrate hangs 25 minutes on Docker-networked Postgres

Symptom: Running migrations... then 25-min silence, then 25× KnexTimeoutError.

Cause: Medusa 2.15.2's lockKnex infers SSL from the DB hostname. A Docker service name (postgres) doesn't match the localhost|127.0.0.1 regex, so SSL gets forced on. Bare postgres:16-alpine doesn't support SSL — handshake fails. Knex's propagateCreateError: false silences the real error; you only see the timeout.

Fix in repo: docker-compose.yml appends ?sslmode=disable to DATABASE_URL for both medusa-migrate and medusa.

If you switch to managed Postgres (RDS, Vultr Managed PG), remove ?sslmode=disable and set sslmode=require instead.

3.2 medusa start fails: "Could not find index.html in admin build directory"

Cause: apps/backend/tsconfig.json overrides outDir to ./dist. Medusa writes admin bundle to dist/public/admin/ but the admin loader looks for ${process.cwd()}/public/admin/index.html. Path mismatch.

Fix in repo: Dockerfile lifts the admin output:

COPY --from=builder /app/apps/backend/dist/public ./apps/backend/public

Do not change tsconfig.outDir without also updating this COPY line.

3.3 Postgres max_connections=200 not applied

Cause: docker compose up -d doesn't recreate an already-running container even if config changed. docker compose restart doesn't reapply config either.

Fix: docker compose up -d --force-recreate postgres. Named volume is preserved — no data loss.

3.4 nginx cert chicken-and-egg

Cause: nginx won't start without certs; certbot standalone needs port 80, which nginx normally owns.

Fix: Follow section 2 exactly — issue cert before starting nginx.

3.5 SAN cert vs separate-cert paths in nginx

Cause: certbot certonly -d X -d Y issues one SAN cert stored under live/<first-domain>/ only. If nginx config had separate ssl_certificate paths per server block, it would fail.

Fix in repo: Both nginx server blocks in infrastructure/nginx/conf.d/tse.conf point at the same SAN cert under live/dev.tse-cartridges.co.za/.

3.6 web container shown as "unhealthy" but actually working

Cause: Healthcheck polled /api/health — route didn't exist.

Fix in repo: apps/web/src/app/api/health/route.ts returns { ok: true }.

4. Cert Renewal

Without make:

docker compose stop nginx

  -v tse-ui_certbot_certs:/etc/letsencrypt \
  -v tse-ui_certbot_www:/var/www/certbot \

# sudo crontab -e
0 3 1 */2 * cd /opt/tse-ui && docker compose stop nginx && docker run --rm -p 80:80 -v tse-ui_certbot_certs:/etc/letsencrypt -v tse-ui_certbot_www:/var/www/certbot certbot/certbot renew --quiet && docker compose up -d nginx >> /var/log/cert-renew.log 2>&1

6. Code-Only Update

cd /opt/tse-ui
git pull origin main
docker compose build medusa web           # only rebuild changed services
docker compose up medusa-migrate          # foreground — wait for exit 0 if migrations changed
docker compose up -d medusa web

If Dockerfile, docker-compose.yml, medusa-config.ts, or nginx config changed, add --force-recreate on affected services.

Always run medusa-migrate before the live medusa container if schema migrations were added.

7. Disaster Recovery

Two stateful pieces:

  1. postgres_data volume — all customer / order / catalogue data: 
    docker compose exec -T postgres pg_dump -U postgres -d tse_medusa --no-owner --clean | gzip > tse_medusa_$(date +%F).sql.gz
    Schedule nightly off-server (Vultr Object Storage, Cloudflare R2, rsync).
  2. certbot_certs volume — TLS certs. Can be reissued from scratch on a new host as long as DNS resolves. Not backup-critical.

Redis and Next.js / Medusa containers are stateless — rebuild from git + image and the data volumes are enough to restore.
